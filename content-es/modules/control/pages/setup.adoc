= Instalación

[[check-system-requirements]]
== Requisitos del sistema

Antes de proceder con la instalación, asegúrese de que su sistema cumpla con los siguientes requisitos mínimos:

* Sistema operativo: Windows, Linux o macOS de 64 bits
* RAM: Mínimo 8 GB (16 GB recomendado)
* Espacio en disco: Mínimo 10 GB de espacio libre
* Java: JDK o JRE versión 21

Verifique su instalación de Java ejecutando:

[source,shell]
----
java -version
----

== Métodos de instalación

[[portable]]
=== Distribución portátil

La distribución portátil le permite ejecutar Flowset Control sin dependencias adicionales (excepto Java). Se distribuye como un JAR de aplicación autónomo y se ejecuta con una base de datos HSQLDB integrada, que se crea automáticamente en el primer arranque — no se requiere ninguna base de datos externa. Ideal para pruebas rápidas o desarrollo local.

+++
<div class="card-block">
  <p>Get the latest Flowset Control distribution package from the official downloads page.</p>
  <a class="primary-btn" href="https://flowset.io/downloads#control" target="_blank">Download</a>
</div>
+++

*Requisitos previos*:

[cols="1,3"]
|===
|Componente |Requisito

|Java |JDK o JRE *17* (Java 21 también es compatible)
|Sistema operativo |Linux, macOS o Windows
|Puerto 8081 |Debe estar libre (configurable, véase más abajo)
|RAM |Al menos *512 MB* disponibles para la JVM
|===

El archivo tiene la siguiente estructura:

[source,text]
----
flowset-control-community/
├── flowset-control-community-2026.0.1-rc.jar   # JAR de aplicación compilado
├── run.sh  / run.bat                           # iniciar la aplicación
├── stop.sh / stop.bat                          # detener la aplicación
├── data/                                       # datos de HSQLDB (se crea automáticamente)
└── README.md
----

*Instrucciones de ejecución*:

. Obtenga el archivo portátil desde la https://flowset.io/downloads#control[página de descargas^] oficial.

. Descomprima el archivo en el directorio de su preferencia. Mantenga intacta la estructura de carpetas — los scripts `run`/`stop` deben permanecer junto al JAR de la aplicación.

. Inicie la aplicación:
+
*Linux/macOS*:
+
[source,shell]
----
chmod +x run.sh
./run.sh
----
+
*Windows*:
+
[source,bash]
----
run.bat
----
+
Al arrancar, el script verifica Java, inicia la aplicación y abre automáticamente el navegador una vez que está lista.

. Acceda a la aplicación en: `++http://localhost:8081++`.
+
Credenciales predeterminadas: `admin`/`admin`. Cambie la contraseña predeterminada inmediatamente después del primer inicio de sesión.

*Detener la aplicación*:

*Linux/macOS*:

[source,shell]
----
./stop.sh
----

*Windows*:

[source,bash]
----
stop.bat
----

*Cambiar el puerto HTTP*:

Si el puerto 8081 ya está en uso, indique un puerto diferente al iniciar:

[source,shell]
----
./run.sh --server.port=8090
----

[source,bash]
----
run.bat --server.port=8090
----

[NOTE]
====
La HSQLDB integrada almacena sus archivos en la carpeta `data/` junto al JAR. Está pensada para evaluación y desarrollo local. Para producción, utilice la xref:database.adoc[configuración de base de datos externa] con Oracle o PostgreSQL.
====

[[docker-compose]]
=== Docker Compose

Este método permite un inicio rápido de Flowset Control en contenedores, sin configuración manual de la base de datos o del entorno.

*Requisitos previos*:

* *Docker* y *Docker Compose*
* Verifique las instalaciones:
+
[source,shell]
----
docker --version
docker compose version
----

*Instrucciones de ejecución*:

. Cree un archivo `docker-compose.yml` con:
+
[source,yaml]
----
version: '3.8'

services:
  postgres:
    image: postgres:15
    environment:
      POSTGRES_DB: flowset-control
      POSTGRES_USER: root
      POSTGRES_PASSWORD: root
    ports:
      - "5432:5432"

  flowset-control:
    image: flowset/flowset-control-community:latest
    environment:
      MAIN_DATASOURCE_URL: jdbc:postgresql://postgres:5432/flowset-control
      MAIN_DATASOURCE_USERNAME: root
      MAIN_DATASOURCE_PASSWORD: root
      SERVER_PORT: 8081
    ports:
      - "8081:8081"
    depends_on:
      - postgres
----

. Inicie los contenedores:
+
[source,shell]
----
docker compose up -d
----

. Acceda a la aplicación en: `++http://localhost:8081++`.

. Para detener los contenedores:
+
[source,shell]
----
docker compose down
----

Encontrará instrucciones detalladas en https://github.com/flowset/flowset-control-community/tree/main/docker-compose[GitHub^].

[[source-code-build]]
=== Compilación desde el código fuente

Compile y ejecute desde el código fuente para desarrollo o despliegues personalizados.

*Requisitos previos*:

* Git
* Java 21 JDK
* Base de datos PostgreSQL

*Instrucciones de ejecución*:

. Clone el repositorio:
+
[source,shell]
----
git clone https://github.com/flowset/flowset-control-community
----
. Configure la base de datos PostgreSQL.
+
Flowset Control almacena datos, como las conexiones al motor BPM, en una base de datos. De forma predeterminada, Flowset Control requiere una base de datos PostgreSQL con los siguientes parámetros:

* Nombre de la base de datos: `flowset-control`
* Nombre de usuario: `root`
* Contraseña: `root`

. Navegue al directorio del proyecto y ejecute:
+
[source,shell]
----
./gradlew bootRun
----

. Acceda a la aplicación en: `++http://localhost:8081++`.

[[wildfly]]
=== Paquete WildFly

Un archivo autónomo que ya incluye el servidor de aplicaciones WildFly con Flowset Control desplegado y preconfigurado. No es necesario descargar WildFly por separado ni realizar un despliegue manual. De forma predeterminada, la aplicación se ejecuta con una base de datos HSQLDB integrada, que se crea automáticamente en el primer arranque, por lo que no se necesita ninguna base de datos externa para empezar.

*Requisitos previos*:

[cols="1,3"]
|===
|Componente |Requisito

|Java |JDK o JRE *17* (Java 21 también es compatible)
|Sistema operativo |Linux, macOS o Windows
|Puerto 8080 |Debe estar libre (configurable, véase más abajo)
|RAM |Al menos *2 GB* disponibles para la JVM
|===

El archivo tiene la siguiente estructura:

[source,text]
----
flowset-control-community-wildfly-2026.0.1-rc/
├── wildfly-40.0.0.Final/                 # servidor de aplicaciones WildFly
│   ├── bin/standalone.conf               # preconfigurado para Flowset Control
│   └── standalone/deployments/
│       └── flowset-control-community-2026.0.1-rc.war   # ya desplegado
├── start.sh / start.bat                  # iniciar el servidor
├── stop.sh  / stop.bat                   # detener el servidor correctamente
└── README.md
----

*Instrucciones de ejecución*:

. Obtenga el paquete WildFly desde la https://flowset.io/downloads#control[página de descargas^] oficial.

. Descomprima el archivo en el directorio de su preferencia. Mantenga intacta la estructura de carpetas — los scripts `start`/`stop` deben permanecer junto a la carpeta `wildfly-*`.

. Inicie el servidor:
+
*Linux/macOS*:
+
[source,shell]
----
chmod +x start.sh
./start.sh
----
+
*Windows*:
+
[source,bash]
----
start.bat
----
+
El arranque tarda aproximadamente 40–60 segundos. Un inicio correcto termina con una línea como `WildFly 40.0.0.Final started in 43443ms`.

. Acceda a la aplicación en: `++http://localhost:8080++`.
+
Credenciales predeterminadas: `admin`/`admin`. Cambie la contraseña predeterminada inmediatamente después del primer inicio de sesión.

*Detener el servidor*:

*Linux/macOS*:

[source,shell]
----
./stop.sh
----

*Windows*:

[source,bash]
----
stop.bat
----

*Cambiar el puerto HTTP*:

Si el puerto 8080 ya está en uso, indique un puerto diferente al iniciar:

[source,shell]
----
./start.sh -Djboss.http.port=8090
----

[source,bash]
----
start.bat -Djboss.http.port=8090
----

*Archivos de registro*:

[source,text]
----
wildfly-40.0.0.Final/standalone/log/server.log
----

*Actualización a una nueva versión*:

Reemplace el archivo WAR en la carpeta de despliegues mientras WildFly está en ejecución — se recarga automáticamente:

[source,shell]
----
cp flowset-control-community-2026.0.1-rc.war \
   wildfly-40.0.0.Final/standalone/deployments/
----

[NOTE]
====
La HSQLDB integrada está pensada para evaluación e instalaciones pequeñas. Para producción, dirija la aplicación a una base de datos externa editando `wildfly-40.0.0.Final/bin/standalone.conf` — descomente el bloque `main.datasource.*` de Oracle *o* PostgreSQL y establezca la URL, el nombre de usuario y la contraseña (o proporciónelos mediante las variables de entorno `FLOWSET_DB_URL` / `FLOWSET_DB_USER` / `FLOWSET_DB_PASS`). Compatible con: *Oracle 19c+* y *PostgreSQL*. Reinicie el servidor después de cambiar la configuración.
====

. Abra su navegador web y navegue a `++http://localhost:8081++`.
