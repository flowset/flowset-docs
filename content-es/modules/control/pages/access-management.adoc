= Gestión de acceso

Flowset Control utiliza el control de acceso basado en roles de https://www.jmix.io[Jmix^] para gestionar los permisos de usuario y proteger el acceso a las funciones de la aplicación. Esta sección explica cómo crear usuarios, asignar roles y configurar permisos para garantizar un funcionamiento seguro del sistema.

[[user-management]]
== Gestión de usuarios

Los usuarios de Flowset Control se definen mediante la entidad https://docs.jmix.io/jmix/security/users.html#entity[User^]. Su información se almacena en la tabla `USER_` de la base de datos configurada.

El sistema incluye un usuario administrador predeterminado con las credenciales `admin`/`admin`, que dispone de todos los permisos de acceso.

[[adding-users]]
=== Creación de usuarios

Para crear un nuevo usuario:

. Inicia sesión en Flowset Control con credenciales de administrador (de forma predeterminada: `admin`/`admin`).

. Ve a la opción de menú *Administration → Users* y haz clic en el botón *Create*.
+
image::add-user-1.png[align="center", width="1428"]
. En la vista *User*, completa los campos requeridos:

* *Username*: Debe ser único.
* *Password* y *Confirm Password*.

. Haz clic en *OK* para guardar el usuario.
+
image::add-user-2.png[align="center", width="1428"]

[[granting-permissions]]
=== Asignación de permisos

Los usuarios recién creados no tienen permisos de forma predeterminada y no pueden iniciar sesión ni utilizar ninguna función.

Para asignar el <<role-management,rol de recurso>> predeterminado con acceso completo:

. Selecciona el usuario de la lista y haz clic en *Role assignments*.
+
image::role-assignment.png[align="center", width="1048"]
. En la sección *Resource roles*, haz clic en *Add*.
+
image::role-assignment-2.png[align="center", width="1051"]
. Selecciona la fila con la etiqueta `Full Access` y haz clic en *Select*.
+
image::role-assignment-3.png[align="center", width="802"]
. Haz clic en *OK* para guardar la asignación de rol.

El usuario ya puede iniciar sesión y acceder a todas las funciones de la aplicación.

[[role-management]]
== Gestión de roles

Los https://docs.jmix.io/jmix/security/resource-roles.html[roles de recurso^] definen los permisos de los usuarios para acceder a objetos y operaciones específicos dentro del sistema, incluidas las operaciones CRUD sobre entidades, atributos de entidad, vistas de la interfaz y otros elementos.

Un administrador del sistema puede crear roles personalizados para implementar un modelo de seguridad granular adaptado a necesidades específicas de la organización.

[[creating-roles]]
=== Creación de roles

Para definir un nuevo rol con un conjunto específico de permisos:

. Ve a la opción de menú *Administration → Roles*.
. Haz clic en *Create* para crear un nuevo rol.
+
image::add-role-1.png[align="center", width="1428"]
. Especifica un *Name* descriptivo y un *Code* único.
. Configura los permisos del rol mediante las siguientes políticas:
+
--
* *Menu policy*: especifica qué elementos del menú principal son visibles para los usuarios que tienen asignado este rol.
* *View policy*: concede permiso para acceder a vistas específicas de la aplicación. Por ejemplo, la vista `Deployments` o la vista `Decisions`.
* *Entity policy*: define las operaciones de creación, lectura, actualización y eliminación (CRUD) permitidas para una entidad de datos. Ejemplo: conceder permisos de _Create_ y _Read_ para la entidad `Deployment`, pero denegar explícitamente el permiso de _Delete_.
* *Entity attribute policy*: controla el acceso de lectura o escritura a atributos específicos dentro de una entidad.
Ejemplo: hacer que el campo `email` de la entidad `User` sea de solo lectura para este rol.
* *Specific policy*: define permisos para funciones específicas con nombre dentro de la aplicación.
--
+
image::add-role-2.png[align="center", width="1163"]
. Haz clic en *OK* para guardar el nuevo rol.

[[row-level-roles]]
== Roles de nivel de fila [.ee]#EE#

[NOTE.ee, caption="Función Enterprise"]
====
Los roles de nivel de fila solo están disponibles en la edición *Flowset Control Enterprise*.
====

Los roles de recursos definen a qué tipos de objetos y pantallas puede acceder un usuario. Los https://docs.jmix.io/jmix/security/row-level-roles.html[roles de nivel de fila^] restringen además el acceso a objetos concretos, por ejemplo a motores BPM determinados. Un usuario sin roles de nivel de fila ve todos los objetos que le permiten sus roles de recursos.

En la edición Enterprise, la pantalla *Roles* (*Administration → Roles*) tiene dos pestañas: roles de recursos y roles de nivel de fila. En la pestaña de roles de nivel de fila puedes crear, editar y eliminar un rol, asignarlo a usuarios y exportar roles a JSON o ZIP.

Control Enterprise también incluye roles predefinidos para responsabilidades habituales: *Process Admin*, *BPM Admin*, *Process Viewer*, *Process Operator*, *Process Release Manager*, *User & Role Admin* y *AI Assistant User*. Cada área, como definiciones de proceso, trabajos o incidentes, tiene además roles separados para lectura, acciones concretas y acceso completo.
