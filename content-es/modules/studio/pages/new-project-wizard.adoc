= Asistente de nuevo proyecto

Usa el asistente de proyectos de Flowset para generar un nuevo proyecto de aplicación BPM en IntelliJ IDEA.

[TIP, caption="Crear un proyecto de aplicación BPM"]
====
1. En el menú principal, ve a *File | New | Project*.
2. En el cuadro de diálogo *New Project*, selecciona *Flowset Project*.
====

== Configuración básica del proyecto

image::new-project-wizard.png[alt="Asistente de nuevo proyecto"]


[cols="1,3", frame=none, grid=rows]
|===
| *Project Name:*
| Especifica un nombre para tu proyecto.

| *Project Path:*
| Especifica la ruta del sistema de archivos de tu proyecto.

| *Build System:*
| Selecciona el sistema de compilación **Gradle** o **Maven**.

| *Group:*
| Especifica el identificador único del grupo, preferiblemente un nombre de dominio inverso que controles, p. ej., `com.example`.

| *Artifact:*
| Especifica el nombre del artefacto dentro del grupo (normalmente coincide con el nombre del proyecto).

| *SDK:*
| Selecciona el SDK de Java para tu proyecto.

| *Java Version:*
| Especifica el nivel de lenguaje de Java.

| *Engine:*
| Selecciona el motor de procesos: **Camunda** u **Operaton**.

| *H2 Database:*
| Selecciona el tipo de base de datos H2: **On-Disk** (persistente) o **In-Memory** (volátil).

| *Camunda (Operaton) Version:*
| Selecciona la versión del motor de procesos (para Camunda u Operaton).

| *Admin Username:*
a|
Especifica el nombre de usuario para la creación automática del administrador.
En el primer inicio, Camunda comprueba si existen usuarios con este ID.
Si no se encuentran, crea una nueva cuenta administrativa.

*Privilegios:*

* Pertenencia al grupo `camunda-admin`
* Permisos `ALL`

| *Admin Password:*
| Especifica la contraseña del usuario administrador.
|===

[WARNING]
====

La creación automática de usuarios es una función exclusiva para desarrollo. No está pensada para uso en producción. En entornos de producción:

* Crea usuarios mediante LDAP/Keycloak
* Añade cuentas mediante migraciones de base de datos

*Advertencia de seguridad:* almacenar contraseñas en `application.properties` las expone en el sistema de control de versiones (Git). Usa siempre:

* Archivos `.env`
* Secretos de Kubernetes
====


== Módulos

[cols="1, 3", frame=none, grid=rows]
|===
| *REST API*
| Proporciona acceso a todas las API principales del motor.
Permite interactuar con el motor mediante solicitudes HTTP.

| *Webapps*
a| Incluye los módulos estándar de Camunda:

* Cockpit: monitoreo y gestión de los procesos en ejecución
* Tasklist: interfaz para completar tareas de usuario
* Admin: interfaz administrativa para la configuración y gestión del sistema

| *Spin (XML & JSON)*
| Camunda Spin es una biblioteca de JVM para el procesamiento simplificado de XML y JSON en Java y lenguajes basados en la JVM (p. ej., Groovy, JavaScript).
Ofrece una API fluida con wrappers ligeros para formatos de datos.

| *Assert*
a| Incluye bibliotecas de pruebas:

* Camunda Assert: pruebas automatizadas de procesos de negocio
* JUnit/Mockito: integración con frameworks de pruebas

| *Security*
| Spring Boot Security proporciona autenticación y autorización para proyectos de Camunda 7.
Protege el acceso a las interfaces de Cockpit, Tasklist y Admin, garantizando que solo los usuarios autorizados puedan gestionar los procesos.

| *Web*
a| El módulo Spring Boot Web añade:

* Servidor web embebido (Tomcat por defecto)
* Spring MVC para la gestión de solicitudes HTTP
* Compatibilidad con controladores REST y serialización JSON

Se integra automáticamente con `camunda-bpm-spring-boot-starter`.
|===


[WARNING]
====
Al añadir Spring Boot Security, la WebSecurityConfiguration predeterminada que se genera abre completamente el acceso a todos los endpoints sin autenticación. Nunca la uses en producción sin modificaciones. Configura siempre las políticas de autenticación, autorización y CORS de acuerdo con los requisitos de seguridad.
====
